Suspicious Process Access To LSASS Memory
high Validated Confidence: Medium
Timestamp 2026-10-01T01:03:15Z
Host WORKSTATION-A
ATT&CK T1003.001
Channel Sysmon / EventID:10
python.exe opened lsass.exe memory with PROCESS_VM_READ (0x1010) access rights. This pattern is consistent with pypykatz / Impacket credential extraction tools. Occurred 16 seconds after the PowerShell-to-Python execution chain (F-02).
Benign Explanation
A Python-based security product could legitimately scan LSASS — no known AV uses python.exe for this.
Limitation
No parent process chain. No network evidence. No dump file creation observed.

Limitations & Caveats

Sample Dataset

Only 3 EVTX files covering a single simulated day. Production analysis requires weeks of logs across multiple systems.

No Script Block Logging

PowerShell Event ID 4104 was not enabled in this sample. The full decoded payload of F-02 is unavailable — cannot confirm destination or C2 address.

No Network Telemetry

Lateral movement, C2 communication, and data exfiltration cannot be confirmed without firewall, proxy, or EDR network logs.

No Account Event Confirmation (F-03)

Event IDs 4720/4738 were not captured. Cannot confirm whether the administrator account modification command succeeded.

Batch File Content Unknown (F-04)

update.bat was not recovered. The persistence payload's intent (e.g., reverse shell vs. credential theft) is unconfirmed.

Rule-Based Detection Only

Hayabusa uses signature-based rules. Novel techniques or living-off-the-land variants not matching existing rules would be missed.
